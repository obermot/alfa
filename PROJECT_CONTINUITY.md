# Незабудка — постоянное состояние проекта и правила продолжения

Этот файл является долговечным источником контекста для следующих чатов, handoff-пакетов и исполнителей. Перед существенными изменениями его нужно читать.

## 1. Канонический репозиторий

- Рабочий репозиторий: `obermot/alfa`.
- Репозиторий публичный.
- Старый `obermot/Nezabudka` не использовать как рабочую базу, но его историю можно использовать для recovery/regression-анализа.
- Не коммитить keystore, пароли, токены, секреты, приватные handoff-файлы и иные чувствительные материалы.

## 2. Текущее приложение

- Android applicationId: `com.nezabudka.alpha.clean013`.
- Текущая версия в `main`: `0.2.1-alarm-screen-alpha`, versionCode `111`.
- Базовый путь создания напоминаний восстановлен из проверенной линии 0.1.5 и снова подтверждён пользователем.
- APK тестируется на физическом Android-смартфоне.

## 3. GitHub Actions — постоянное правило экономии

- Обычные коммиты в `main` не должны запускать сборку.
- Контрольная сборка вызывается через изменение `ci/BUILD_REQUEST` либо вручную через workflow dispatch.
- Связанные изменения пакетировать и запускать один осмысленный build.
- Не перезапускать workflow вслепую; сначала анализировать причину ошибки.
- Workflow: `.github/workflows/android-build.yml`.

## 4. Постоянная тестовая подпись APK

Введена постоянная тестовая подпись, чтобы новые APK устанавливались поверх предыдущих без удаления приложения.

Repository Secrets:

- `NEZABUDKA_KEYSTORE_B64`
- `NEZABUDKA_KEYSTORE_PASSWORD`
- `NEZABUDKA_KEY_ALIAS`
- `NEZABUDKA_KEY_PASSWORD`

Значения секретов нигде публично не хранить. Сам keystore не находится в репозитории; резервная копия хранится у владельца проекта. Подпись нельзя менять без отдельного осознанного решения.

Контрольная сборка №3 2026-09-19 подтвердила корректность постоянной подписи.

## 5. Цикл доставки

1. Внести пакет изменений без запуска Actions.
2. Один раз изменить `ci/BUILD_REQUEST`.
3. Дождаться результата того же run.
4. Скачать artifact ZIP.
5. Извлечь из него настоящий APK.
6. Передать APK пользователю в чат.
7. Пользователь устанавливает поверх текущей версии и тестирует.

## 9. Alarm Screen

По решению пользователя введён отдельный видимый `AlarmActivity`. В будущем это должен быть расширяемый тревожный экран: можно будет назначать цвета, режимы, дополнительные элементы и другие тревожные свойства.

Текущая архитектура:

- notification использует `full-screen intent` на `AlarmActivity`;
- manifest содержит `USE_FULL_SCREEN_INTENT`;
- activity может показываться поверх lock screen и включать экран;
- если Android не разрешает автоматический full-screen запуск, нажатие на notification открывает тот же экран;
- на экране есть кнопки `Ответить голосом`, `Услышал / выключить`, `+10 минут`;
- распознавание голосового подтверждения выполняется только при видимой activity, поскольку `RECORD_AUDIO` на современных Android является while-in-use permission;
- используется штатный Android `SpeechRecognizer`, без новой тяжёлой зависимости.

Open Source / Android Search Gate для этой функции выполнен.

## 10. Фактический тест 0.2.0

Пользователь подтвердил:

- напоминания принимаются и голосом, и текстом;
- напоминания срабатывают;
- срабатывание работает даже во время просмотра видео;
- audio focus работает: звук видео приглушается во время напоминания;
- после голосового создания UI мог оставаться в состоянии, похожем на продолжающееся прослушивание, и требовал повторного нажатия;
- голосовое подтверждение после `Вы услышали?` не принималось;
- `Вы услышали?` звучало слитно с основным текстом, нужна пауза;
- отдельное редактирование имени ещё отсутствовало.

## 11. Изменения 0.2.1

В `0.2.1-alarm-screen-alpha` внесены точечные исправления поверх подтверждённого рабочего пути создания reminder:

- `MainActivity` снова показывает отдельное редактируемое поле имени и кнопку `Изменить имя`;
- после сохранения имя явно подтверждается строкой `Имя сохранено: ...`;
- системный `SpeechRecognizer` в основном экране теперь полностью уничтожается после завершения/ошибки и создаётся заново при каждой новой попытке;
- это должно устранить зависшее состояние `Говорить/Стоп` и нестабильность первой попытки;
- перед фразой `Вы услышали?` добавлена настоящая TTS-пауза 800 мс;
- handoff к голосовому подтверждению сделан долговечным: готовность слушать сохраняется в SharedPreferences, поэтому сигнал не теряется, если AlarmActivity зарегистрировалась позднее;
- AlarmActivity при `onStart` проверяет сохранённую готовность и автоматически запускает распознавание ответа;
- ручная кнопка `Ответить голосом` остаётся fallback;
- подтверждения `да`, `услышал/услышала`, `понял/поняла`, `хорошо`, `ладно`, `готово`, `сделал/сделала`, `всё`, `хватит`, `отмени`, `не напоминай`, `я уже встал/встала` и близкие варианты переводятся в штатный `ACTION_ACK`.

Контрольная сборка GitHub Actions №7 для 0.2.1 успешно прошла 2026-09-19: постоянная подпись, компиляция и artifact upload завершены успешно.

## 13. Правило handoff

Каждый следующий handoff должен явно передавать:

- `obermot/alfa` как канонический публичный repo;
- обязательность чтения этого `PROJECT_CONTINUITY.md`;
- экономный GitHub Actions workflow;
- Open Source Search Gate;
- постоянную APK-подпись и имена четырёх Secrets, но никогда не их значения;
- запрет менять signing key;
- recovery-базу 0.1.5 / 0.1.9;
- архитектуру Alarm Screen;
- текущую версию 0.2.1;
- последний фактический тест пользователя и следующий незавершённый шаг.

Существенные новые решения и результаты тестов нельзя оставлять только в памяти чата — их нужно записывать сюда или в другой явно связанный долговечный проектный артефакт.
