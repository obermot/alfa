# Незабудка — постоянное состояние проекта и правила продолжения

Этот файл является долговечным источником контекста для следующих чатов, handoff-пакетов и исполнителей. При продолжении разработки его нужно читать до внесения существенных изменений.

## 1. Рабочий репозиторий

- Канонический рабочий репозиторий: `obermot/alfa`.
- Репозиторий публичный.
- В разработке больше не использовать старый `obermot/Nezabudka` как рабочую базу.
- В публичный репозиторий нельзя добавлять keystore, пароли, токены, секреты, приватные handoff-файлы и иные чувствительные материалы.

## 2. Текущее приложение

- Android applicationId: `com.nezabudka.alpha.clean013`.
- Текущая тестовая линия: clean alpha.
- Текущая версия в `main`: `0.1.8-clean-alpha`, versionCode `108`.
- APK предназначен для установки и тестирования на физическом Android-смартфоне.

## 3. GitHub Actions — постоянное правило экономии

GitHub Actions используется только для осмысленных контрольных сборок.

- Обычные коммиты в `main` не должны автоматически запускать сборку.
- Контрольная сборка вызывается отдельно через узкий триггер `ci/BUILD_REQUEST` либо вручную через workflow dispatch.
- Перед запуском Actions следует пакетировать связанные изменения и делать один контрольный build.
- Нельзя перезапускать workflow вслепую. При ошибке сначала анализируется причина.
- Чтение статуса, логов, артефактов и репозитория не является поводом для нового запуска.
- Существующий успешный build можно использовать как подтверждение собираемости неизменённого состояния.

Workflow: `.github/workflows/android-build.yml`.

## 4. Постоянная подпись APK

Начиная с контрольной сборки 2026-09-19 введена постоянная тестовая подпись APK.

Цель: все последующие тестовые APK должны устанавливаться поверх предыдущей версии без конфликта подписи и без удаления приложения.

### 4.1. Хранение ключа

- Сам keystore НЕ хранится в Git-репозитории.
- Резервная копия keystore хранится у владельца проекта локально.
- `.gitignore` блокирует `*.jks`, `*.keystore`, `*.p12`, `*.pem`, `*.key`, `.env*`, `secrets.*`, `credentials.*`, `keystore.properties`, `signing.properties` и другие чувствительные файлы.
- Значения секретов никогда не записывать в этот файл, issue, commit, PR, workflow log или публичный код.

### 4.2. GitHub Repository Secrets

Для подписи используются четыре Repository Secrets:

- `NEZABUDKA_KEYSTORE_B64`
- `NEZABUDKA_KEYSTORE_PASSWORD`
- `NEZABUDKA_KEY_ALIAS`
- `NEZABUDKA_KEY_PASSWORD`

Имена можно хранить публично; значения — только в GitHub Secrets и резервной копии владельца проекта.

### 4.3. Механизм сборки

- Workflow восстанавливает keystore из `NEZABUDKA_KEYSTORE_B64` только во временной среде GitHub runner.
- Gradle получает путь к восстановленному keystore и параметры подписи через переменные окружения / secrets.
- `app/build.gradle.kts` содержит явный signingConfig для постоянной тестовой подписи.
- Если секреты подписи отсутствуют в обычной локальной среде, локальная debug-сборка не должна раскрывать или требовать секреты из репозитория.

### 4.4. Проверка

Контрольная сборка GitHub Actions №3 (`ci: verify persistent APK signing`) успешно завершилась 2026-09-19.

Успешно прошли шаги:

- Restore signing keystore
- Build signed debug APK
- Upload artifact

Это подтверждает, что Base64 keystore, пароль хранилища, alias и пароль ключа настроены корректно.

### 4.5. Правило для будущих версий

- Нельзя менять signing key без отдельного осознанного решения владельца проекта.
- Все новые тестовые APK из `obermot/alfa` должны подписываться этим же постоянным ключом.
- Потеря этого ключа означает потерю возможности обновлять уже установленную тестовую ветку тем же package ID без удаления приложения.

## 5. Текущий цикл доставки тестовой версии

Предпочтительный рабочий процесс:

1. Изменения вносятся в `obermot/alfa` без лишних Actions.
2. Связанные изменения накапливаются в один осмысленный тестовый пакет.
3. Выполняется одна контрольная сборка через `ci/BUILD_REQUEST`.
4. Из GitHub Actions забирается APK-артефакт.
5. APK передаётся пользователю в текущем чате.
6. Пользователь открывает тот же чат на смартфоне, скачивает APK и устанавливает его.
7. Пользователь тестирует и сообщает фактическое поведение.

USB, Android Studio и локальная сборка на ноутбуке для обычного тестового цикла не требуются.

## 6. Open Source Search Gate

Перед добавлением нетривиальной новой возможности нужно сначала проверить существующие зрелые open-source решения / библиотеки / SDK / reference implementations.

При сравнении учитывать минимум:

- качество результата;
- лицензию и допустимость использования;
- безопасность;
- приватность;
- совместимость с Android/Kotlin и текущей архитектурой;
- размер и сложность зависимости;
- поддержку и зрелость;
- офлайн-возможности;
- стоимость эксплуатации.

Нельзя подключать тяжёлую зависимость только потому, что она существует. Если текущая лёгкая реализация объективно лучше для приложения, это допустимое решение.

## 7. Последние исправления линии 0.1.7

Перед переходом на постоянную подпись были внесены и сохранены следующие изменения:

- расширены естественные подтверждения напоминаний, включая «всё», «я уже встал/встала», «можно не напоминать» и близкие формулировки;
- убран искусственный 9-минутный запрет повторного срабатывания, который мешал законным коротким интервалам;
- автоматический повтор неподтверждённого напоминания остаётся через 10 минут;
- счётчик `Напомнила: N раз` очищается при подтверждении, переносе и удалении;
- просроченные активные напоминания восстанавливаются после reboot / возврата exact alarm permission / изменения времени;
- ручной `+10 минут` заменяет существующий alarm того же reminder;
- recurring-напоминание при подтверждении отменяет старый alarm и планирует следующий цикл.

## 8. Тест пользователя 0.1.7 и исправления 0.1.8

Фактический тест 0.1.7 на смартфоне выявил:

- приложение спрашивает имя и произносит подтверждение «Хорошо, Алексей», но интерфейс не показывает однозначно, что имя сохранено;
- после неудачного голосового распознавания приложение предлагает повторить, но повторный запуск распознавания может не принимать речь;
- текстовый ввод в этом состоянии может маршрутизироваться неправильно и не восприниматься как напоминание.

В `0.1.8-clean-alpha` внесены исправления:

- режим захвата имени отделён от обычного ввода; обычный текст больше не трактуется как имя только потому, что имя пустое;
- имя после сохранения явно отображается как `Имя сохранено: <имя>`;
- кнопка сохранения имени активна только при изменении введённого имени;
- системный Android `SpeechRecognizer` пересоздаётся для каждой новой попытки и уничтожается после завершения/ошибки, чтобы повтор после `onError` начинался с чистого состояния;
- тексты после ошибки распознавания явно предлагают повторно нажать `Говорить` либо ввести напоминание текстом;
- базовый `TemporalParser` отдельно проверен: поддерживаемые естественные временные фразы продолжают маршрутизироваться в создание напоминания.

## 9. Правило handoff

Каждый следующий handoff должен явно передавать как минимум:

- рабочий репозиторий `obermot/alfa`;
- публичный статус репозитория;
- ссылку/указание на этот `PROJECT_CONTINUITY.md` как на обязательный источник контекста;
- правило экономии GitHub Actions;
- правило Open Source Search Gate;
- наличие постоянной APK-подписи;
- имена четырёх signing secrets, но НИКОГДА не их значения;
- запрет менять signing key без явного решения;
- текущую версию приложения и последний успешный контрольный build;
- фактический результат последнего тестирования пользователем и следующий незавершённый шаг.

Если состояние проекта меняется существенно, этот файл следует обновлять тем же рабочим циклом, не оставляя изменения только в памяти чата.
